## Map

- `src/lib/server/db/`: `app.schema.ts` (app tables, Drizzle `pg-core`), `auth.schema.ts`
  (generated by the Better Auth CLI; regenerate, don't hand-edit), `schema.ts` re-exports
  both. `index.ts` is the Postgres layer (postgres-js pool, `getDb`, `first`/`one`,
  `advisoryLock`, `runMigrations`); `testing.ts` gives tests a database (`createTestDb`);
  `supabase-lockdown.ts` revokes Supabase's REST roles at startup.
- `src/lib/server/auth.ts`, `src/lib/permissions.ts`: auth setup (Google, GitHub, Discord
  social sign-in) and team roles (owner / editor / viewer via organization access control).
  `src/lib/server/demo/`: the demo sandbox. `src/lib/server/designs/gallery.ts`: the shared
  design gallery. `src/lib/server/analytics.ts`: cookieless analytics.
- `src/lib/server/startup.ts`: migrate + Supabase lockdown + seed on server start (async,
  awaited by the `init` hook).
- `src/lib/server/seed/`: template seed data (`types.ts` is the contract, `tmt.ts` the
  MakeGood kit, `index.ts` the list); see its README.
- `src/lib/domain/`: pure, framework-free logic (no DB, Svelte or Node imports).
  `types.ts` is the shared contract (`BuildView`, `PartState`, `PrintRun`, `PartPatch`;
  change it deliberately, it binds server, domain and UI). `accounting.ts`, `actions.ts`,
  `now.ts`, `grouping.ts`, `format.ts`; `fixtures.ts` builds a test `BuildView` from the seed.
- `src/lib/server/access.ts`: `ApiError`, `requireMember/Editor/Owner`, `buildAccess`
  (non-member → 404, viewer write → 403).
- `src/lib/server/builds/`: `view.ts` (`loadBuildView`), `create.ts` (`createBuild`
  snapshots the design), `actions.ts` (every mutation goes through `mutateBuild`).
- `src/lib/server/events.ts`: in-process pub/sub per build (single container; SSE at
  `/api/builds/[id]/events`). `src/lib/server/teams.ts`: chapter helpers (writes go
  through Better Auth `auth.api`).
- `src/lib/client/`: `api.ts` (typed fetch helpers that throw the server's message),
  `live.ts` (`subscribeBuild` EventSource with reconnect), `printer-store.svelte.ts`.
- `src/lib/components/`: UI; `build-context.svelte.ts` holds the live view and `act()`
  (mutate, then re-fetch the view).
- `src/lib/server/compress.ts`: gzip for html/json responses (wired in `hooks.server.ts`)
  and cached gzip for GLB downloads.
- `src/routes/(site)/`: public pages (`/` home, `/demo`, `/privacy`, `/terms`); a signed-in
  visitor to `/` is redirected to `/workspace`.
- `src/routes/(app)/`: signed-in area (layout guard → `/login`; `/workspace` → active
  workspace): `builds/[id]/` tabs, `teams/[slug]`, `onboarding`, `studio`, `designs`,
  `gallery`, `account`, `admin`, `help`, `about`. `src/routes/invite/[id]` and `/login` sit
  outside the groups. `src/routes/api/`: JSON endpoints;
  `/api/health` for the Docker healthcheck.
- `drizzle/`: committed SQL migrations (one baseline, `0000_baseline.sql`).
  `.github/workflows/public-ci.yml`: CI (check, lint, unit, build, e2e on Postgres, image
  build) and the image publish to GHCR from `main`.
- `e2e/`: Playwright specs, `fixtures.ts`, `helpers.ts`.

## Build state (`build-state`)

- Design locks and slot removal (#34): `PartDef.defaultRole`, `PartDef.locked` (from
  `builds.design.lockedParts`), `FilamentRole.kit` (template slot, not removable).
  `server/builds/role-keys.ts` `remapRoleKey` moves role-keyed grams (plates, part profiles,
  upload `filamentMap`) when a slot is removed. `design.update` activity payload parts:
  `palette {label, reset, kept}` (label "previous" = undo), `locked`/`unlocked`,
  `lockedAdded`, `removed` + `replacedBy`.
- `domain/guards.ts`: the one `isObj` / `Obj` plain-object guard; server, printer and kit pack
  modules import it instead of defining their own.
- **Mutations:** `mutateBuild` (users) / `mutateBuildSystem` (printer-driven) in
  `src/lib/server/builds/actions.ts`: access check → domain function → patches + `activity`
  row in one transaction → SSE emit. State rules live in `src/lib/domain/actions.ts` and
  return `PartPatch[]`.
- **Run history is the source of truth** for run-driven statuses: `recompute.ts`
  (`recomputeParts`) replays a part's runs through `applyRun`; `deleteRun`/`updateRun`
  recompute targeted parts (`?recompute=0` to skip). Undo right after logging:
  `POST /api/builds/[id]/runs/[runId]/undo` with a client snapshot.
- **Live printer jobs win over run history:** `applyRun`/`recomputeParts` take
  `opts.livePrinting` (slugs on a `printing`/`paused` printer job of the build, from
  `livePrintingSlugs(tx, buildId)` in `builds/actions.ts`). A Failed/Partial run, a run
  delete/edit, or an undo leaves such a Printing part untouched (a retry is on the bed);
  Success still prints it. `printingAction` 'start' takes `startedAt` from the build's active
  linked job (clamped to now) and the estimate from the printer's `last_status`
  (`elapsedSec + remainingSec`), via `startPrinting(view, slugs, now, live)`.
- **Variants:** `templates.variant_groups`, `builds.variant_choices`, `domain/variants.ts`.
  `BuildView.parts`/`state`/`plates` hold active parts only; `allParts` has everything.
- **Not printing (#113 of the sibling):** `build_parts.skipped` is a read-time filter in
  `loadBuildView`: inactive = variant-inactive ∪ skipped, for `parts`, `state` and plate
  parts. `build_plates.parts` is never rewritten; a plate with every part skipped
  disappears. `view.skipped` lists them; `list.ts` and `startedBuildIds` ignore skipped
  rows. Restore keeps the stored status and never recomputes from runs. Assembly steps stay
  (`filterSteps` 4th argument). The arranger, planner and export read `view.parts`. Route
  `POST /api/builds/[id]/parts/skip`; async `skipParts` / `skipPartsTx(tx, view, slugs,
skip)` (inside another mutation, no activity row). A Printing or live part is refused
  (409). Demo users may skip and restore.
- **Custom pieces, read side:** a `build_custom_pieces` row becomes one `PartDef` per plate
  (section 'Custom', `custom.pieceId`) in `view.parts`, never in `allParts`;
  `designParts(view)` is what design UI iterates, and designs resolve slugs through
  `allParts`, so a custom slug cannot enter `design.partRoles`. Plates are `build_plates`
  rows with `source = 'custom:<pieceId>'`. `domain/custom.ts`: `partBySlug`, `kitOnly`,
  caps. Accounting: a custom plate trusts its file's role map, a custom part takes its
  plate's grams. `remapRoleKey` / `removeSlot` re-key custom part roles. Activity kinds
  `part.skip`, `part.restore`, `custom.add`, `custom.remove` are in `REARRANGE_KINDS`;
  `custom.rename` is not.
- **Workspaces:** every user has a personal workspace (organization with metadata
  `{ personal: true, userId }`, "My builds", created on sign-up and lazily for legacy users
  in `teams.ts`). Personal workspaces can't take invitations. Builds move personal → chapter
  via `POST /api/builds/[id]/move`.
- **Drafts (Studio):** a `builds` row with `kind = 'draft'`. Hidden from
  `buildRows`/`recentBuilds` (default `kind = 'build'`), team page, Builds menu and printer
  job matching (`findPlateForFile`, `linkJob`, `expect`); `draftRows` lists them.
  `mutateBuild`/`mutateBuildSystem` refuse any activity kind outside `draftAllows` with 400;
  `setSetupStep` and `phase` edits are refused too. UI: Design, Files, Settings tabs only
  (others redirect to Design); Settings shows a printer/layout summary linking to Files.
  Editors can delete drafts. `POST /api/builds/[id]/promote` sets `kind = 'build'`,
  `setup_step = 5`, writes `build.promote`, and opens the wizard at Export.
- **Log a whole plate:** `LogPlateButton` opens `LogRunSheet` with `quick` (Success,
  finished now, time = started→now if Printing else the plate's per-run time, grams =
  slicer/learned grams per run). Sheet shows "Print 1 of 2" on multi-run plates.
- **Pace** (`domain/pace.ts`): sum(actual)/sum(plate time) over successful timed
  whole-plate runs; ignores failed/partial, subset runs, hours <30% or >300% of plate time,
  and hours exactly equal to the plate time (an unedited prefill). Needs 12 estimated hours.
  Each run is compared with the time it printed against (`print_runs.est_seconds`).
  `PlateTime.svelte` shows "≈ 9.4 h at your pace · slicer 10 h"; Now printing's ETA uses
  the pace when no printer job reports its own.
- **Run choice on per-part plates** (`domain/run-choice.ts`): perPartRuns plates (rims,
  plate 13) print one part per physical print. Default (`defaultRunParts`): the part
  already Printing, else the first part not Printed with runs left; never all.
- **Grams** (#45, `domain/accounting.ts`): `partGrams(view, slug)` and `plateGrams(view, plate)`
  are the one source order, returning `{perRun, total, source, approx, unknown[]}`. Part:
  typed `build_parts.manual_grams` (total for all copies) > your slice
  (`partProfiles.gramsByRole` × qty) > BOM (all copies, never × qty). Plate: typed
  `slicer_grams` (source 'user') > the file total (source 'file', or 'slice' for arranged or
  learned plates) > the sum of its parts (weakest source, `approx`, `unknown` lists parts
  without weight). `estPerRun`, `unitUsed` (logged grams + the estimate for done runs no
  Success log covers), `filamentStats` (`unknownParts`), `splitGramsByRole`, `now.ts`,
  `LogRunSheet` and `printer-match.ts` all use them. `build_plates.slicer_grams_source` is
  inferred for older rows by `gramsSourceOf` (`server/builds/view.ts`). `updatePart`
  `manualGrams` (0-20000 g, 0/null clears, activity `part.grams`, drafts refused);
  request-supplied part slugs go through `hasPart` (own keys only).
- **Started builds** (#56): `domain/started.ts` `buildStarted(view, live)` /
  `startedSummary` define "started" (any run, a part not To print, a Printing part, a live
  printer job); `BuildView.started` carries it (`loadLiveJobs` in `view.ts`).
  `autoRearrange` skips started builds. `server/builds/started-guard.ts`
  `BuildStartedError` is a 409 `build-started` with `started` and `summary` (`respond()`
  passes `extra` fields); the client `call()` throws `ApiError {status, code, body}`.
  Activity: `design.recolor` (outside `REARRANGE_KINDS`), `design.apply` with `mode`, and a
  `before` snapshot `{roles, partRoles, lockedParts}` in design payloads.
- **Stats** (#47, `domain/stats.ts`, pure): `runsByPeriod`, `plateTimes` (shares
  `timedRun` with `pace.ts`), `filamentBreakdown`, `failureRates`, `progressSeries`,
  `projectFinish` (28-day rate; fewer than 3 runs → `not-enough`), `buildStatsSummary`
  (numbers and build names only, no personal data) and `workspaceStats`. Failed = not
  Success; a split Partial's two rows count as one failed print (paired one-to-one,
  order-independent). Dates are `YYYY-MM-DD` with Monday weeks. `safeSwatch` only passes
  `#rrggbb`. `server/stats/workspace.ts` `loadWorkspaceStats`: member-only (404), drafts
  excluded, `months` clamped 1-24, loads each build with `loadBuildView`, no cache.
  Shared helpers (dates, rounding, `attempts`/`isSplitPair`, failure-rate types) live in
  `domain/stats-core.ts`; `stats.ts` re-exports them. The failures chart counts part-level
  Failed runs too (a plate row, or "Not on a plate"). Hours round alike for good and failed
  (whole hours from 100 h logged).
- **Headline numbers** (`domain/kpis.ts`, pure): `buildKpis(view, now)` is the one source
  for the four headline figures (parts, time, filament, finish, each with its estimate),
  used by the Stats tiles and the build header cards.
- **Kept vs lost** (#46, `domain/accounting.ts`): `unitUse`/`unitUseByRole` split used grams
  into kept (Success runs, plus the estimate for done runs no Success log covers) and lost
  (Failed runs and older Partial rows); `used = keptG + lostG`, and `TimeStats` has
  `keptHours`/`lostHours`. `stockKg(f)` = `spools` (starting kg) + Σ `spoolAdds[].kg`;
  `haveGrams` comes from it, as do `SlotPanel` and `RemoveColorDialog`. `partWeights` and
  `weightShare` give the shared per-part weighting; `runRoleGrams` lives here
  (`spool-split.ts` re-exports it). On a single-run, non-perPart plate with some parts
  Printed, `unitLeft` and the time left count only the unprinted parts' share.
- **Partial with per-part results** (#46): `logrun.ts` `splitPartial` turns one Partial into a
  Success run (ticked parts) and a Failed run (the rest), both with `partSlugs`; hours and
  `estSeconds` split by weight. `partialPrefill`: Kept = ticked parts' full share, Lost =
  the rest × progress %. `runOutcome` in `server/builds/actions.ts` saves both in one
  `mutateBuild` with one `run.add` row (`split: true`, `runIds`); `addRun` returns
  `{runId, runIds}`; `undoRun` takes `runIds` (cap 10, this build only) and writes one
  `run.undo`. Offered only for ≥2 targets, not perPartRuns, runs ≤ 1. `PartialParts.svelte`
  is shared by `LogRunSheet` and `ConfirmPrintLog`. Run grams are capped at `MAX_RUN_GRAMS`
  (100000).
- **Spool adds** (#46): `build_filaments.spool_adds` JSON (`SpoolAdd` in `app.schema.ts`);
  `addSpool`/`removeSpoolAdd` (POST `api/builds/[id]/filaments/[role]/stock`, DELETE
  `.../stock/[addId]`) go through `mutateBuild` (kg 0.01-99, note ≤ 200 chars with control
  characters collapsed, ≤ 100 adds per slot, drafts refused); activity
  `filament.stock.add`/`.remove`; `view.ts` resolves the adder's name.
- **Filament by role** (`domain/accounting.ts`): a sliced file's grams per role
  (`Plate.filamentGrams`) go through `plateFileRoleGrams(plate, partRoles)`, which keeps
  only roles that a part on the plate has (a file's slot → role map can disagree with the
  design: stray TPU slots on PETG plates). `roleShares`/`filamentStats` use the kept grams
  renormalized; `estPerRun` delegates to the Grams helpers below;
  no overlap → the parts' own roles. `runRoleGrams` uses the same helper for whole-plate
  runs.
- **Part print logs:** `partRuns(view, slug)` in `logrun.ts` includes whole-plate runs
  that cover the part; `RunTable` tags them "Plate N · whole plate".
- **Activity:** every activity kind needs a sentence in `describeActivity` /
  `describeActivitySegments` (`domain/activity.ts`); payload text is control-char stripped
  so it can't forge links. `ActivityList` links to `/print#plate-N` / `#part-<slug>`; the
  Print tab applies non-persisted overrides, scrolls and flashes 2 s.
- **Print tab toolbar:** stored per build in localStorage `tmt-ui:<id>` as
  `{ role, hide?, group }`, grouped by Plate by default (see Print toolbar below).
- **Quotas and caps** (`server/quota.ts`): every creation path calls
  `assertUnder(tx, key, count, {userId})` in the same transaction as its insert, after an advisory lock on the quota
  scope (`quota:<key>:<scope>`), so two requests cannot both pass the count; a refusal is a
  `QuotaError` (409, or 429 for slots) with `{error, code: 'quota'}`; `null` limit = no
  query; only site admins are exempt. Bytes are measured from files on disk
  (`workspaceUploadBytes`, `userUploadBytes`), never from client sizes; `assertUploadRoom`
  before writing, `enforceStreamedUpload` after streaming. Slots: `acquireSseSlot`,
  `acquireUploadSlot`. Constants: 2000 runs per build (`assertRunRoom`,
  `assertRunTotal`), activity pruned to the newest 5000 per build (`pruneActivity`).
- **Live streams** (`server/live-stream.ts`): shared SSE response; re-checks access on every
  event and, with session validity, on each 25 s heartbeat; releases its slot once.
- **Kit copies and builds**: `createBuild` refuses a copy owned by another workspace;
  `moveBuild` and deletions call `builds/repoint.ts` `repointBuildsOffTemplates` (other
  workspaces' builds go back to the copy's base kit).
- **Write rate** (`server/write-rate.ts`, called in `hooks.server.ts` after the session is
  resolved): token bucket per user on every non-GET request except `/api/auth/*`
  (`WRITE_RATE_PER_MIN` default 120, `WRITE_RATE_BURST` default 60); refusal shaped for the caller
  (action failure, HTML page, or JSON `{error, code: 'rate'}`).
- **Printer job linking**: a job links to a plate only by file name or by one bound
  expectation ("Start on <printer>", `jobId` in org settings, `ExpectedConfirm.svelte`);
  never guessed. `jobNeverStarted` (domain/actions.ts) releases a cancelled print without
  logging filament; progress is monotonic (`maxProgress`).

- **Start/log control**: `PlateControl.svelte` is the one control (Start printing / Finish &
  log / Take off printer / Log a print…) on Print, Files, the Now card and the landing;
  props `plate`, `only?`, `size?`, `alwaysLog?`. `PlateStart` and `LogPlateButton` are
  retired.
- **Optimistic actions**: `BuildCtx.act(fn, { patches })` applies `applyPatches`
  (`domain/actions.ts`) at once, rolls back on failure, and the re-fetched view always wins.
  `setPartStatus`, `startParts`, `takeOffParts`, `restoreParts` each push a 15 s Undo toast
  (`UNDO_MS`). Logging a run is not optimistic.
- **Print toolbar**: `PrintToolbar.svelte`; one row with a Filter sheet on phones, not
  sticky. Stored per build as `{ role, hide?, group }` in `tmt-ui:<id>`; "Hide printed"
  defaults on once a part is Printed; parts that become Printed during a visit stay visible
  ("Printed just now", `groupParts(..., { keep })`). Specs use `keepPrintedVisible`.

## Plates and 3MF (`plates-3mf`)

- **Plate replacement guard** (#56): `guardPlateReplace` (`builds/plates.ts`) runs before
  `setPlateLayout`, `arrangeForPrinter` and `applyUpload` (plates mode, or template mode
  with arrange): a live printer job refuses (409 `build-started`, no override); a started
  build needs `confirm` (or the older `convertRuns`). `client/plate-guard.ts`
  `withStartedConfirm` is shared by `PlateLayoutPicker`, `PlatesPanel` and `PlateUpload`,
  which also disable those controls up front while a job is live (`plates-refused`).
- Plate grams (#45): an upload sets `slicer_grams_source='file'`; typed plate grams survive
  re-layout and re-upload (`manualTimes` → `PlateManuals`, `carryManuals` in
  `arrange-plan.ts`). `domain/plate-grams.ts` `plateGramsBadge` + `PlateGrams.svelte` show
  grams per run (with a total for multi-run plates) next to `PlateTime` on the Print tab,
  NowCard, NextUp and PlatesPanel; a plate with parts without weight shows "≥ N g · k parts
  without weight" with a quick add form.
- Files tab layouts: `PlatesPanel` fetches the build's layouts and passes them to
  `PlateLayoutPicker` as `preload`; answers are latest-wins (numbered requests) and
  `onchanged` invalidates older ones. The picker applies a `preload` only when the object
  changes. Props such as `ctx.id` are getters over the whole view: read them untracked in
  effects that must not re-run on every refresh.
- **Implied bed for built-in layouts:** a build with no printer gets `view.layoutPrinter`
  from its MakeGood layout key (`layoutBed` in `src/lib/printers/layout-bed.ts`: `xpa` =
  Bambu X1 / P1 / A1 256 × 256, `h2d` = H2D / H2S 350 × 320, both 4 slots), derived in
  `loadBuildView` and never stored. The setup wizard, `PlatesPanel`, `ExportCard` and the
  export (`buildExportPlan`, `prepareExport`) fall back to it; arranging, re-arranging,
  printer jobs and uploaded 3MFs still need `view.printer`. A new tuned layout gets an
  implied bed by adding it to `LAYOUT_BEDS`.
- **Export follows the chosen layout:** `prepareExport` uses the stored arrangement when the
  build is arranged; when the build's plates are a MakeGood layout whose bed equals the export
  printer's (`kitLayoutFor`: `layoutBed(current key)`, 0.5 mm), it follows the Print tab's plates
  (same numbers, names, runs, parts) and places each plate's parts flat with `placeOnPlates`
  (`builds/arrange-plan.ts`; one `arrange()` per plate, Z rotation only). A plate that needs more
  than one bed keeps its number for the first bed; the rest goes to "<name> (continued)" plates
  numbered after the last, with a note naming the plate. Only a layout for another bed, an
  uploaded file, no plates, or a stale arrangement gives the "fresh arrangement" note, which says
  to use "Arrange for my bed" / "Re-arrange plates" on the Files tab. No separate "arrange now"
  button: choosing the layout is enough.
- **Arranger:** `domain/arrange.ts` (see `arrange.README.md`). Flat rotations only
  (no 3D re-orientation code exists: removed 2026-11-11; `seed/arrange-tmt-snapshot.test.ts` pins the flat arranger's output); 1 mm default edge margin, 8 mm between parts, max
  clearance to edges and keep-outs; rigid source groups only when per-piece packing would
  split a part (wings, footrest, harness). "rotated N°" is shown on the part, never as a
  warning. Reference result: Elegoo Centauri Carbon 256 × 256 with the cutter keep-out, kit
  pack 1.0.1 → 21 plates, no warnings, export guard clean.
- **Layouts:** built-in `template_plate_layouts` (`xpa` default, `h2d`),
  `builds.plate_layout`. Named "MakeGood's Bambu ... profile" in the UI. Switching to a
  MakeGood profile while plates are arranged or uploaded asks first.
- **3MF parsing** (`src/lib/server/threemf/`): Bambu, Orca family, plain; reads `Metadata/*`
  only, never `3D/Objects/*`. Files on disk are read through the zip central directory
  (`zipfile.ts`); never fflate `Unzip` on a path. Elegoo 2.4 keeps plates in
  `model_settings.config` without instances, so objects come from `slice_info.config`
  (`identify_id`, `_id_N_copy_N` tail stripped); names use underscores (the matcher
  normalises). Limits: `maxThreeMfBytes()` (`MAX_3MF_MB`, default 1024), STEP zips 200 MB,
  `BODY_SIZE_LIMIT=1100M`. The browser sniffs big files with `File.slice` (`openBlobZip` in
  `client/kit-probe.ts`).
- **Matching and apply:** matcher `domain/plates-match.ts`; apply in `builds/plates.ts`
  (`applyUpload`). Plate-attached runs must be converted to per-part runs (`convertRuns`).
  Upload review offers "Use these plates" or "Use as print template" (default template when
  the build has a printer or arranged plates).
- **Twin parts** (`domain/twins.ts`): parts sharing a source file (rims `rims-1-4` accent,
  `rims-2-3` primary). An object mapped to a twin puts all active twins on the plate,
  `perPartRuns` true, runs = ceil(runsHint / twins) (warning when not divisible),
  `slicer_by_part` = plate grams per run per twin. "Use only <part>" overrides. Startup
  repair `repairTwinPlates` (`builds/twin-repair.ts`) fixes older uploads, idempotent.
- **Print template** (learned per-part data, `build_part_profiles`):
  `domain/part-profile.ts`, `builds/part-profiles.ts`. **exact** when G-code names objects
  (`domain/gcode-objects.ts`, run by `threemf/gcode-stats.ts`, 4 min budget), else
  **volume-split**. A part's grams count under its current role, so a recolor moves grams.
  Files tab "Print template" card; `DELETE /api/builds/[id]/print-template`. Not wired yet:
  "printer" and "manual" profile sources.
- **Plate time precedence:** manual (user) > slicer > learned > MakeGood profile > estimate
  (`domain/time-estimate.ts` splits MakeGood plate times by BOM grams; `estRough` for
  variant guesses). Manual times: `build_plates.manual_est_seconds` + `manual_est_source`
  ('user' | 'printer'), set in Files (`SlicerTimeInput`), from the Now card, or a printer
  job link (never over 'user'). `syncPlateTime` in `builds/actions.ts`. No time at all →
  dash and "no time estimate yet".
- **Files tab:** "Use my own sliced file" card (and drop anywhere) opens `PlateUpload` as a
  modal; the kit drop zone hands sliced projects to it (`BuildCtx.slicedFile`). With a
  printer set, `PlateLayoutPicker` shows a one-line `printerSummary()`. In build mode
  `PlatesPanel` owns the single `plates/layouts` fetch and hands it to the picker through
  `preload` (`null` = loading: heading seeded from the plates' `source`, select disabled).
- **Custom pieces and saved custom parts:** `builds/custom-pieces.ts` (`addCustomPiece`
  from a parsed upload with typed `times` / `grams`, `insertCustomPieceTx` as the single
  insert path, `renameCustomPiece`, `removeCustomPiece`), `builds/custom-plates.ts`
  (`detachCustomPlates` around the three whole-build deletes of `build_plates` in
  `setPlateLayout`, `applyUpload` and `writePlan`; thumbnails at
  `plates/<buildId>/custom-<hex>.png`, path recomputed, never trusted from the row), and
  `custom-library.ts` (`workspace_custom_pieces`: per-plate summaries only, no file, no
  thumbnail; save, create by hand, edit, refresh from a build, apply; role keys are the

## Printers and camera (`printers`)

Printers reach the server **only through OctoEverywhere shared links**; there are no LAN
connections, no discovery, no custom camera URLs and no Spoolman in this edition. A printer
can also be added "not connected" (kind `manual`) to log prints by hand.

- Read-only adapters in `src/lib/server/printers/adapters/`: `sdcp.ts` (Elegoo), `moonraker.ts`
  (Klipper), `octoprint.ts`; `index.ts` picks one and reports offline (nothing dialled) when a
  printer has no usable link. **No write command exists:** every SDCP request is built by
  `sdcpEnvelope`, which accepts only `SDCP_READ_COMMANDS` (0 and 1, empty data);
  `SDCP_ALLOWED_COMMANDS` (writes) is `[]`. Through a link the Elegoo adapter sends Cmd 1 once
  and then relies on pushed status.
- **Shared links** (`src/lib/printers/share-link.ts`): the link
  (`https://shared-<token>.octoeverywhere.com`) is a secret `shareLink` in `secretEnc`
  (`secrets.ts`, AES-GCM, key derived from `BETTER_AUTH_SECRET`), never returned (only listed
  in `secretsSet`). Elegoo: status over `wss://<link>/websocket`, MainboardID learnt from the
  first push. Klipper: https and wss to the link host, `/access/oneshot_token`. OctoPrint:
  polled through pinned requests (10 s active, 30 s idle). `printers.host` holds the
  placeholder `octoeverywhere` (or `manual`) and is never dialled. `parsePrinterInput`
  (`store.ts`) validates the form; `safeError` / `maskSecrets` (`types.ts`) keep the link host out of
  every `OutboundError`, `CameraError` and adapter message.
- **Connection options** (`src/lib/printers/connection-options.ts`, `GET /api/printers/options`):
  `octoeverywhere-elegoo | octoeverywhere-klipper | octoeverywhere-octoprint | manual`;
  `PrinterPublic.connection` is `link | manual`. Setup text in `setup-steps.ts`; chooser
  grouping in `integrations-view.ts`. Printers are added and edited on the workspace
  Integrations page (`IntegrationPrinters`, `PrinterForm`); `/teams/[slug]/printers` is the
  status view. Caps (in the store transaction, advisory-locked): link printers per workspace
  and site-wide (`QUOTA_LINK_PRINTERS_TOTAL`), manual printers per workspace. Demo users cannot
  add printers.
- **Outbound guard** (`server/printers/outbound.ts`): every printer and camera connection goes
  through `assertOutboundAllowed` / `resolveAllowed` / `guardedFetch`. The only destination is
  a shared-link host (`isShareLinkHost`), and only on calls that pass `allowShareLink`; every
  DNS answer must be global unicast (`isGlobalUnicast`), the connection is pinned to the
  validated address, https on the default port, redirects never followed. Any other host is
  refused before DNS with `LINK_ONLY_MESSAGE`. Never use `fetch`, `net`, `dgram` or a
  WebSocket on a user-supplied host anywhere else.
- **Camera** (`camera-source.ts`, `camera.ts`, `mjpeg.ts`, `camera-access.ts`): sources come
  from the link only: Elegoo `<link>/video` (MJPEG, no snapshot), Moonraker
  `/server/webcams/list`, OctoPrint webcam settings, all checked by `checkCameraUrl`
  (`src/lib/printers/camera-url.ts`) and pinned to the link host on every hop; remote camera
  lists capped at 4. The hub keeps one upstream per printer fanned out, latest frame kept,
  closed 30 s after the last viewer, 5 MB frame cap, 5 s connect / 15 s stall timeouts. Routes
  `GET /api/printers/:id/camera|/snapshot|/stream` (members, 404 otherwise),
  `POST /api/printers/camera-test` (editors). UI: `CameraTile` on the Now printing card,
  collapsible (`tmt-camera-collapsed:<id>`; no requests while collapsed); its enlarged view is
  a `ds-modal` dialog.
- **Remote data limits**: `MAX_REMOTE_MESSAGE_BYTES` (1 MiB per message before parsing),
  `MessageBudget` (100 messages and 2 MiB per second), 10 s handshake timeout, silence close
  (`LINK_SILENT_CLOSE_MS`, 120 s), `linkBackoff` (10 s to 5 min), `HostileGuard` (long backoff
  after an oversize frame), `safeFileName`/`safeText`, MainboardID `[A-Za-z0-9_-]{1,64}`, 16
  filaments; `mergeStatus` skips `__proto__`/`constructor`/`prototype`. Test routes
  (`test-limit.ts`): 10 per minute per user, uniform failures.
- **Secrets and destinations** (`store.ts` `secretsForLink`): stored secrets belong to the
  link they were saved for; changing the link needs its secrets re-entered. Caps:
  `assertLinkRoom` / `assertManualRoom`.
- **Supervisor** (`supervisor.ts`, started from `startup()`): one adapter connection per
  enabled link printer, mirrors the latest status into `printers` (throttled), pushes it to
  the team's SSE stream and drives the job lifecycle.
- **Jobs:** the supervisor emits a `job` event on job create/link/finish. Link/expect take
  optional `partSlugs` on per-part plates. Dismissing a job with no logged run releases its
  Printing parts (`printer.job.release`). Auto-link needs plate numbers in file names.
  Linking (`attach` → `linkPatches`): the job's start and estimate replace a part's Printing
  state unless another live job (`heldByOtherJobs`) covers the part; ended, unlogged jobs and
  manual starts never hold a part. A printer-sourced plate time follows; a typed one stays.
  Run-time numbers go through `sanePrintSeconds` (`domain/format.ts`). `printers/status.ts`
  `unloggedEndedJobs` / `unloggedNotice` drive `UnloggedNotice.svelte`. `manual` printers:
  `expect` returns `{ manual: true, printer }`.
- **Partial job confirm** (#46): `confirmJobRuns` (`printers/jobs.ts`) passes a validated
  `split` to `addRun` and returns `{runId, runIds}`; the job's `run_id` is the kept run.
  `ConfirmPrintLog` offers Partial with `PartialParts` and Kept/Lost grams prefilled from the
  job's progress. Nothing is sent to the printer.
- **Tracking:** `printing.start` carries an optional `printer` name in its activity payload;
  `startedOnPrinter` (`domain/activity.ts`) prefills the log sheet; `StartOnPrinter` links a
  running unlinked job at once; `betweenRuns` (`domain/actions.ts`) marks a part waiting for
  its next run.
- **Client store** (`client/printer-store.svelte.ts`): `printerStoreFor(ctx, …)` keeps one
  store per build context and retargets it on each `acquire()`; sequence-guarded `load()`;
  one reference-counted `OrgStream` (a single `EventSource`, window listeners, 30 s poll) per
  organization; refetch on SSE reopen / visibilitychange / online / focus; "Printer status
  unavailable · Retry". "Your printers" lists printers of every workspace the user is in
  (`GET /api/printers/mine?first=<org>`).
- **Job linking UI**: `JobLinkControl` (never guesses a plate), used by `PrinterJobs` (build
  page) and `PrinterJobLink` (Printers page). `GET /api/printers?org=` returns `builds` and
  `expected` for editors only. A disabled printer reads "Monitoring stopped".
- Mocks for tests: `mock-sdcp.ts`, `mock-camera.ts` (unit tests only; there is no e2e seam for
  link printers yet, see STATUS).

## Kit and startup (`kit-and-startup`)

- **Migration `0003_custom_parts`** (additive): `build_parts.skipped`, `build_custom_pieces`,
  `workspace_custom_pieces` (`library_id` on a build's piece has no foreign key). The
  Supabase lockdown is schema-wide and covers both tables.

- **Postgres layer** (`db/index.ts`): postgres-js pool (`DATABASE_POOL_MAX`, default 10;
  `prepare: false`), Drizzle `pg-core`. Every query is awaited; `first`/`one` replace
  `.get()`; helpers that may run inside a transaction take `DbOrTx`; `advisoryLock(tx, name)`
  serialises check-then-insert paths. Porting patterns and pitfalls (jsonb key order, `23505`,
  no `rowid`): `docs/dev/plans/public-site-db-port.md`.
- **Migrations:** one baseline, `drizzle/0000_baseline.sql`, regenerated freely until the
  first deploy of the live site; after that, new migrations only (`0001_…`). `runMigrations`
  runs them in one transaction behind `pg_advisory_xact_lock`, so containers starting together
  are safe. The self-hosted SQLite chain, its legacy upgrade and the release fixtures do not
  exist here. Tests: `db/migrate.test.ts`, `startup.test.ts` (cold start twice on an empty
  database from `createEmptyTestDb()`).
- **Test harness:** `db/test-global-setup.ts` builds one migrated template database per run;
  `createTestDb()` clones it (about 30 ms) per file or test; `TEST_DATABASE_URL` (default
  `tmt_test` on the local server); `scripts/dev-postgres.sh clean` drops leftovers.
- **Supabase lockdown** (`db/supabase-lockdown.ts`): after migrations on every start, revokes
  the `anon` and `authenticated` roles' privileges on the app's tables, sequences and functions
  (and default privileges) and enables RLS with no policies; a no-op on plain Postgres. Tested
  on plain Postgres only (`supabase-lockdown.test.ts`).
- Startup order: migrations, the Supabase lockdown, then `cleanupAuthDataAtStartup` (`server/auth-cleanup.ts`:
  idempotent, one transaction, clears `session.ip_address` and unused account tokens, logs
  one counts-only line only when something changed), then seeding and the kit pack.

- Kit pack format, env (`KITPACK_DIR`, `KITPACK_URL`, `KITPACK_DOWNLOAD=off`) and how to
  build one: `docs/kit-pack.md`. Seed data contract: `src/lib/server/seed/README.md`.
- Startup: migrate → seed reconcile (`seed/run.ts`, upserts template data, never touches
  builds) → `backfillBuildParts` → `repairTwinPlates`.
- 3D model: STEP zip → `src/lib/server/models/` (forked worker bundled by
  `vite.worker.config.ts`, ~80 s / ~620 MB peak) → GLB with one node per slug in each

## Release and deployment (`release-pwa`)

- Version: `src/lib/version.ts` (`APP_VERSION`, the `version` field of `package.json`, inlined
  at build time) is the one source, shown on `/about` and returned by `/api/health` as
  `{ ok: true, version }` (503 stays `{ ok: false }`).
- CI (`.github/workflows/public-ci.yml`; top-level permissions read-only): on pull requests
  into `main`, pushes to `main` and manual runs. `test` (Postgres 16 service,
  `TEST_DATABASE_URL`): `npm ci`, check, lint, unit tests, build. `e2e`: the full Playwright
  suite against `tmt_e2e` (`E2E_DATABASE_URL`), report uploaded on failure. `image`: a
  `docker buildx build` without push (the kit pack is downloaded and verified; no
  `KITPACK_OPTIONAL`). `publish` (only on a push to `main`, after all three, the only job with
  `packages: write`): builds `linux/amd64` and pushes
  `ghcr.io/ayostepht/tmt-build-tracker-public:latest` and `:sha-<short>`. No docs-only fast
  path, no release tags, no `edge`. Issue forms live in `.github/ISSUE_TEMPLATE/` (bug,
  feature request, hosting or docs feedback, printer connection report; the app's
  Experimental note links to the last).

- Docs for operators: `README.md` holds the intro, screenshots and a guide list;
  `docs/guides/hosting.md` is the full hosting walkthrough (Supabase, OAuth apps, Cloudflare,
  Fly.io / Railway / own server with a Cloudflare Tunnel, Unraid, backups, security
  checklist); other guides: printers, environment, troubleshooting, phone-install,
  site-admin, slicer-export. Deploy files in `deploy/` (`docker-compose.yml` with the tunnel,
  `fly.toml`, `railway.json`). A new env variable goes in `guides/environment.md` and
  `.env.example`. Contributor docs:
  `CONTRIBUTING.md`, `SECURITY.md`, `.nvmrc` (22).
- Origins: see `CLAUDE.md` Stack (`scripts/proxy-origin.mjs`, `PUBLIC_URL`). The preload
  strips any inbound `x-tmt-forwarded-original` and sets it only when the client itself sent
  a forwarding header; `client-ip.ts` `shouldWarnUndeclaredProxy` reads only that marker for
  the one-time "reverse proxy" log hint (never for trust). `writeRateResponse` gets the host
  for its back link from `event.url.host`.
- Image: `ghcr.io/ayostepht/tmt-build-tracker-public` (`latest`, `sha-<short>`), kit pack
  baked in (downloaded at build time from the sibling repository's release, see
  `docs/kit-pack.md`), runs as `node`, `VOLUME /data`, `HEALTHCHECK` on `/api/health`,
  `NODE_ENV=production`, `BODY_SIZE_LIMIT=100M`, `MAX_3MF_MB=95` (Cloudflare's free plan
  refuses bodies over 100 MB).
  `three` and `pdfjs-dist` are devDependencies: browser-only, bundled by Vite into
  `build/client` (the pdf.js worker is a hashed static asset), so `npm prune --omit=dev`
  leaves them out of the image. Keep it that way: nothing on the server may import them.
- **PWA**: `static/manifest.webmanifest` (light colors; dark `theme-color` via media meta tags
  in `src/app.html`), icons in `static/icons/`, `static/offline.html` (self-contained, no app JS).
  `src/service-worker.ts` (SvelteKit registers it; imports `immutable`/`assets` from
  `$app/manifest`, `version` from `$app/env`) precaches those and answers only: cache-first
  precached files and `/_app/immutable/*`; versioned (`?v=`) kit GLBs via a runtime cache; a
  failed page navigation gets `/offline.html`. Rules live in `src/lib/client/sw-rules.ts`
  (never `/api/*`, `/invite`, non-GET, HTML documents). No `skipWaiting` until
  the page posts `SKIP_WAITING` (`src/lib/client/pwa.ts`, started from `+layout.svelte`, shows a
  toast with Reload). `scripts/response-defaults.mjs` sends `Cache-Control: no-cache` for the
  worker, manifest and offline page. Needs a secure context (https, or localhost in dev).
  The model runtime cache (`RUNTIME_CACHE` in `sw-rules.ts`) is bounded to 12 entries (oldest
  evicted) and is the only cache that can hold per-user content: `clearPrivateCaches()` in
  `pwa.ts` deletes it (never the shell precache) and sign-out / account deletion call it.
  Hardening: the shell rule is exact membership in the precache list (no `/_app/immutable/`
  prefix; paths with `%` or `..` never match) and stores only `basic` 200 responses;
  `putModel` swallows quota errors. The pdf.js worker (`isPrecacheExcluded`, 1.27 MB, kit guide
  import only) is not precached: it loads from the network on demand (guide import needs
  connectivity); precache is about 2.3 MB. A 401 from any `/api/` call in `client/api.ts`, and
  sign-out, call `clearPrivateCaches()` (`client/private-caches.ts`), which also posts on
  `BroadcastChannel('tmt-auth')`; `initPwa` listens so other tabs clear too.
  `src/service-worker.ts` is excluded from svelte-check (`tsconfig.json`); `npm run build`
  type-checks it.
- **Request pipeline** (`hooks.server.ts`): boot validation (`bootProblems`, exit 1) → body
  cap by route (`body-limits.ts`, default 1 MB) → `/api/auth/*` to Better Auth with a trusted
  client address (`client-ip.ts`: `CF-Connecting-IP` when `TRUST_CLOUDFLARE=1`, otherwise
  `ADDRESS_HEADER`/`XFF_DEPTH`; fails closed, and refuses `/api/auth/*` without the header) → session →
  write rate → resolve with security headers (`security-headers.ts`; page CSP with nonces in
  `vite.config.ts`). `scripts/response-defaults.mjs` (preloaded by `proxy-origin.mjs`, must
  be copied into the image) adds default headers to static files and errors.
- **Limits by configuration**: `quotas()` (hosted defaults: 10 teams per user, 50 builds per
  team, 1 GB uploads per team, site-wide account and sign-up caps; table in
  `docs/guides/hosting.md`), `maxThreeMfBytes()` (`MAX_3MF_MB`, default 95),
  `minFreeDiskBytes()` / `diskHasRoom()` (default 2048 MB), `WRITE_RATE_*`, `DEMO_*`; all
  validated at boot (`bootProblems`, which also requires `BETTER_AUTH_SECRET`, an https
  `PUBLIC_URL`, a complete provider, `ADMIN_EMAILS` and a trusted proxy in production).
- **Analytics** (`server/analytics.ts`, `components/Analytics.svelte`): `ANALYTICS_PROVIDER`
  = `plausible | umami | cloudflare`, off when unset. Only that provider's script loads and
  only its exact origins are added to the CSP (`security-headers.ts`). Page views only: no
  query or hash, ids after `/builds/`, `/teams/`, `/designs/`, `/gallery/` become `:id`,
  `/api/*` and `/invite/*` never reported, nothing for `DNT: 1` or `Sec-GPC: 1`. Cookieless;
  the only cookies are the session and the demo session.
- Dependabot: npm weekly, actions monthly, both into `main`.
