# Troubleshooting

Start with the container log (`fly logs`, Railway's **Deployments > Logs**, or `docker compose -f deploy/docker-compose.yml logs -f app`). Lines from the app begin with `[tmt]`.

| Symptom                                                                 | Cause and fix                                                                                                                                                                                                                                                                                                                                                                                                           |
| ----------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Container stops with `Refusing to start: configuration problems`        | The lines after it list each problem: a missing or weak `BETTER_AUTH_SECRET`, a `PUBLIC_URL` that is not a bare `https://` origin, no sign-in provider (or one with only an ID or only a secret), no `ADMIN_EMAILS`, no trusted proxy (`ADDRESS_HEADER` or `TRUST_CLOUDFLARE=1`), leftover `OIDC_*` variables, or a malformed limit. See [What the server checks at start](hosting.md#3-make-the-secrets-and-settings). |
| "Cannot connect to database" or the container restarts at start         | Check the `DATABASE_URL`: the Supabase **Session pooler** string (port 5432), `?sslmode=require` at the end, special characters in the password URL-encoded, and the Supabase project not paused.                                                                                                                                                                                                                       |
| Sign-in returns to an error page                                        | The callback URL registered at the provider must be `<PUBLIC_URL>/api/auth/callback/<provider>` exactly, with https and no trailing slash.                                                                                                                                                                                                                                                                              |
| Every sign-in attempt returns 400, or everyone shares one sign-in limit | The client address is not read correctly. `TRUST_CLOUDFLARE=1` is set but requests do not come through Cloudflare (no `CF-Connecting-IP`), or `ADDRESS_HEADER` names a header your proxy does not send. See [Client address and proxies](environment.md#client-address-and-proxies).                                                                                                                                    |
| The admin pages do not appear for the admin                             | The email in `ADMIN_EMAILS` must be the verified email of the account you signed in with (Google, GitHub or Discord). Check the email shown on your account page.                                                                                                                                                                                                                                                       |
| Forms fail with "Cross-site POST form submissions are forbidden" or 403 | The site was opened through an address other than `PUBLIC_URL` (for example `<app>.fly.dev` while `PUBLIC_URL` is your domain). Use the `PUBLIC_URL` address.                                                                                                                                                                                                                                                           |
| A 3MF upload fails with 413 or a Cloudflare error                       | The file is over `MAX_3MF_MB` (95 MB by default, because Cloudflare's free plan refuses larger request bodies). A project sliced with G-code for every plate can be larger than that; upload the project without G-code. If your proxy allows larger bodies, raise `MAX_3MF_MB` and `BODY_SIZE_LIMIT` together.                                                                                                         |
| Uploads fail with 507                                                   | The data volume has less free space than `MIN_FREE_DISK_MB` (2048 MB by default). Grow the volume or free space.                                                                                                                                                                                                                                                                                                        |
| An action is refused with a message about a limit                       | A per-account limit was reached (teams, builds, uploads, designs and others). The operator can change them, see [Limits](environment.md#limits).                                                                                                                                                                                                                                                                        |
| Changes from other people appear only after a reload                    | Something between the browser and the app buffers the live-update stream. Behind your own proxy disable buffering for `/api/builds/*/events`, see [Your own reverse proxy](hosting.md#path-c-your-own-server-with-a-cloudflare-tunnel-recommended-for-security).                                                                                                                                                        |
| A printer shows offline                                                 | Check in OctoEverywhere that the printer is online and the shared connection still exists. See [Printers](printers.md#problems).                                                                                                                                                                                                                                                                                        |
| Printer links ask to be entered again, or everyone was signed out       | `BETTER_AUTH_SECRET` changed. Restore the original value; otherwise enter the links again.                                                                                                                                                                                                                                                                                                                              |
| The standard kit's 3D model or print files are missing                  | Check the log for `[tmt] kit pack:` lines. The pack is inside the image and installs a few seconds after start; a failure is logged and retried at the next start. If it needs a download (`KITPACK_URL`), the container needs internet access and `KITPACK_DOWNLOAD` must not be `off`.                                                                                                                                |
| A demo cannot be started                                                | `DEMO_MAX_LIVE` demos already exist (`0` turns the demo off), or this address started `DEMO_PER_IP_PER_HOUR` demos in the last hour. Expired demos are removed every 15 minutes.                                                                                                                                                                                                                                        |
